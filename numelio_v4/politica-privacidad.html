2. Qué datos se pueden tratar

  • Cuenta: correo electrónico, identificador de usuario y datos necesarios para autenticación y gestión de la cuenta.
  • Contenido aportado: texto, apuntes, PDF, archivos TXT e imágenes que el usuario decida cargar o enviar a una función de estudio.
  • Uso de IA: instrucciones, preguntas y contenido de archivos que se envíen para generar o corregir exámenes, crear tarjetas o responder consultas.
  • Historial académico dentro del servicio: el código revisado contempla guardar resúmenes de resultados de exámenes, como asignatura, título, puntuación y fecha. Debe confirmarse el esquema exacto en producción.
  • Datos técnicos y de seguridad: registros de uso, fecha/hora, función solicitada e identificador de cuenta o hash de IP para aplicar límites y prevenir abusos. Un hash de IP no debe considerarse automáticamente anónimo.
  • Suscripción: información de estado y referencias técnicas de facturación si se habilita Numelio Pro. Los datos de pago se procesan a través de Stripe; debe verificarse exactamente qué datos recibe el titular.

3. Finalidades y bases jurídicas

Los datos se utilizarán para crear y mantener la cuenta, prestar las funciones solicitadas, guardar los materiales que el usuario elija conservar, gestionar la suscripción si se activa, proteger el servicio, aplicar límites de uso y atender solicitudes o reclamaciones.

PENDIENTE DE VALIDACIÓN: el responsable debe asignar y documentar una base jurídica adecuada para cada finalidad (por ejemplo, ejecución del servicio solicitado, obligación legal, interés legítimo debidamente ponderado o consentimiento cuando corresponda). No se debe utilizar una aceptación genérica de esta política como consentimiento para finalidades distintas.

4. Proveedores y destinatarios

Según el código y la configuración revisados, se utilizan o están previstos los siguientes proveedores: Supabase para autenticación y servicios de datos; Anthropic para procesar solicitudes de inteligencia artificial; Render para alojar el servicio; Stripe para pagos y suscripciones cuando se habiliten; y jsDelivr para servir la biblioteca cliente de Supabase desde una CDN.

Cuando una función de IA requiere contenido aportado por el usuario, ese contenido se transmite a Anthropic para procesar la petición. Antes de publicar, el responsable debe verificar contratos, funciones activas, subencargados, ubicación del tratamiento y posibles transferencias internacionales de cada proveedor. No se afirma aquí que todas las integraciones estén activas en producción.

5. Conservación y eliminación

Los datos se conservarán durante el tiempo necesario para prestar el servicio y atender obligaciones legales. Los plazos concretos para cuenta, materiales, historial, registros técnicos y copias de seguridad están pendientes de definir y verificar. Debe documentarse cómo se elimina una cuenta y qué ocurre con sus materiales, registros y copias de respaldo. No se publicará un plazo numérico hasta comprobar que puede cumplirse técnicamente.

6. Derechos de las personas

Cuando proceda, puedes solicitar acceso, rectificación, supresión, oposición, limitación del tratamiento y portabilidad, así como retirar un consentimiento previamente otorgado. Escribe a [PENDIENTE: correo de privacidad @numelio.es]. También puedes reclamar ante la Agencia Española de Protección de Datos. El responsable deberá habilitar un procedimiento para verificar y responder las solicitudes dentro de los plazos legales.

7. Menores

Numelio puede ser utilizado por estudiantes menores de edad. El responsable debe establecer información clara y adecuada a la edad, y comprobar las reglas aplicables tanto al consentimiento para tratar datos personales como a la capacidad para contratar una suscripción. En España, el artículo 7 de la LOPDGDD establece reglas específicas para el consentimiento de menores de catorce años; esto no resuelve por sí solo la capacidad de contratar servicios de pago. No se deben cargar datos personales de terceros sin base legítima.

8. Seguridad

Se aplican medidas técnicas destinadas a proteger cuentas, solicitudes y materiales. Antes del lanzamiento deben verificarse los permisos de base de datos y almacenamiento, las claves de servidor, los registros, la eliminación de archivos temporales, las copias de seguridad y el procedimiento de gestión de incidentes.

9. Cambios y contacto

Esta política podrá actualizarse si cambian las funciones, proveedores o requisitos legales. Se indicará la fecha de actualización y, cuando corresponda, se informará de los cambios relevantes.
